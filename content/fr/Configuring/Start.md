> [!NOTE]
> Vous cherchez l'ancienne syntaxe hyprlang ? Consultez les [pages du wiki 0.54](https://wiki.hypr.land/0.54.0/).
> Depuis Hyprland 0.55, hyprlang est devenu obsolète au profit de lua.

La configuration se trouve dans `$XDG_CONFIG_HOME/hypr/hyprland.lua`. Dans la plupart des cas,
cela correspond à `~/.config/hypr/hyprland.lua`.

Vous pouvez demander à Hyprland d'utiliser un fichier de configuration spécifique en utilisant l'argument
`--config` (ou `-c`).

Hyprland génère automatiquement un exemple de configuration pour vous si vous n'en avez pas. Vous pouvez trouver un exemple de configuration
[ici](https://github.com/hyprwm/Hyprland/blob/main/example/hyprland.lua).

En supprimant la ligne contenant `hl.config({ autogenerated = true })`, vous supprimerez l'avertissement
jaune.

La configuration est rechargée dès que vous l'enregistrez. Cependant, vous pouvez utiliser
`hyprctl reload` pour recharger la configuration manuellement.

> [!WARNING]
> La configuration par défaut n'est pas complète et ne répertorie pas toutes les options / fonctionnalités
> de Hyprland. Veuillez consulter cette page du wiki ainsi que les pages liées plus bas
> ici pour obtenir des instructions de configuration complètes.

## Style et syntaxe du langage

Hyprland utilise [Lua](https://lua.org/) pour son fichier de configuration. Il s'agit d'un langage de script simple
et performant utilisé dans diverses parties de logiciels.

### Conseils sur Lua pour Hyprland

#### Exemple de configuration

Elle est [ici](https://github.com/hyprwm/Hyprland/blob/main/example/hyprland.lua).

#### Utilisation de plusieurs fichiers de configuration

Diviser la configuration d'hyprland entre plusieurs fichiers est un moyen plus simple de gérer la configuration. Pour charger ou référencer d'autres fichiers, nous utilisons la fonction [require](#require) de lua. 

Vous pouvez référencer les fichiers en utilisant des chemins relatifs à l'emplacement de `hyprland.lua`. Exemple :

```lua
-- refers to $XDG_CONFIG_HOME/hypr/awesomeconf/keybinds.lua
require("awesomeconf/keybinds")

-- refers to $XDG_CONFIG_HOME/hypr/awesomeconf/animation.lua
require("awesomeconf.animation")
```
Vous pouvez utiliser `/` ou `.` comme séparateur de répertoire. Le séparateur `/` est spécifique à UNIX tandis que le séparateur `.` est générique.

Vous pouvez également utiliser des caractères génériques ou des chemins absolus :

```lua
require("./stuff/*")
require("/usr/share/among/us.lua")
```

#### Autocomplétions

Nous fournissons des stubs Lua générés automatiquement dans le répertoire `meta/` du dépôt. Vous pouvez configurer
votre LSP pour les charger automatiquement. Ce fichier est généralement installé dans `/usr/share/hypr/stubs/`.

#### Require

Utilisez `require()` pour charger d'autres fichiers dans votre configuration. Cela est **fortement** recommandé
car chaque appel à `require()` est spécifiquement traité par Hyprland comme un
scope lua distinct, de sorte que les erreurs dans un fichier `require()` n'empêchent _pas_ l'exécution des autres fichiers.

Il est important de noter que de nombreuses erreurs interrompront l'exécution d'un fichier lua donné.
Le comportement en cas d'erreur est décrit plus bas.

> [!WARNING]
> Le comportement protecteur de `require()` ne s'applique pas au chargement des modules. Si vous
> essayez de charger un module qui n'existe pas, `require()` provoquera une véritable erreur
> dans le fichier depuis lequel il a été appelé. Autrement dit, si vous faites
> `require("nonexistent")` dans votre configuration principale de Hyprland, *l'exécution de votre configuration principale
> sera interrompue*, comme décrit ci-dessous.
>
> Si vous souhaitez empêcher de telles erreurs de provoquer des problèmes, ou même les détecter et y
> réagir à l'exécution, utilisez la fonction `pcall()` de lua, par exemple :
> ```lua
> local status, value = pcall(require, "maybe-nonexistent")
> if status then
>   print("successfully loaded module, it returned:", value)
> else
>   print("failed to load module, its error message was:", value)
> end
> ```

> [!TIP]
> Pour les utilisateurs avancés qui souhaitent ignorer complètement la séparation des scopes de Hyprland,
> la fonction `require` originale de lua est disponible sous le nom `__require`. Elle peut être
> utilisée directement ou restaurée comme valeur par défaut en définissant `require = __require`.
> Cette dernière option peut être particulièrement utile si vous chargez des
> modules tiers qui sont incompatibles avec le comportement de protection contre les erreurs de Hyprland.

#### Comportement en cas d'erreur

Hyprland essaie autant que possible de rendre les erreurs non destructives. Cependant,
cela n'est pas toujours possible :
 - Les erreurs fondamentales de syntaxe lua empêcheront Hyprland de recharger votre configuration et afficheront une erreur
 - Les erreurs de syntaxe lua à l'exécution interrompront l'exécution du fichier lua actuel et afficheront une erreur (par ex. appeler un `nil`)
 - Les erreurs de type Hyprland à l'exécution continueront l'exécution et afficheront une erreur (par ex. passer une chaîne au lieu d'un flottant à `hl.*`)
 - Les erreurs à l'exécution lors d'une exécution asynchrone (par ex. une fonction de raccourci clavier) afficheront une notification concernant l'erreur

Si vous lancez Hyprland et que vous avez une erreur majeure avant vos raccourcis clavier, dans le même fichier,
ces raccourcis ne seront évidemment pas chargés.

Pour atténuer cela, Hyprland vous fournira quelques raccourcis clavier d'urgence (SUPER+Q, +R et +M pour le terminal, l'exécution et la sortie respectivement)
et le mentionnera dans la fenêtre d'erreur.

#### Boucles infinies, événements réentrants

Hyprland dispose de protections pour empêcher les scripts qui s'exécuteraient indéfiniment de faire planter
la session. Ces protections arrêteront votre script lorsqu'un délai / une limite donnée aura été atteint.

#### Bibliothèque standard

Les bibliothèques standard de lua sont chargées par défaut. Les scripts Lua peuvent exécuter
du code arbitraire sur votre machine, assurez-vous de faire confiance à la source de votre configuration.

#### Tester avec le REPL

L'API et l'état Lua peuvent être facilement explorés avec le [REPL Lua intégré à hyprctl](../Advanced-and-Cool/Using-hyprctl/#repl).
