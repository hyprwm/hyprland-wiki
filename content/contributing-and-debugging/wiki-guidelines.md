## Wiki engine notes

Hugo automatically concatenates pairs of lines unless a newline or a double space is present at the end of the first line in the pair.

Template can be invoked by \{\{< shortcode >\}\} or \{\{% shortcode %\}\}.
The correct usage can be found in the shortcode file.

Hextra theme's shortcodes can be found [here](https://github.com/imfing/hextra/tree/main/layouts/_shortcodes).
Wiki's shortcodes can be found [here](https://github.com/hyprwm/hyprland-wiki/tree/main/layouts/_shortcodes).

Version selector is generated by a template, that reads a list of versions in Hugo's `config.toml`

## General styling notes

All styling described here must apply everywhere, unless it is not possible, e.g.: splitting one table field in markdown to fit multiple sentences rule.

Different classes of information must be separated by 1 newline, except HTML comments.

If paragraph consisnt of multiple sentences, each sentence must go a separate line.

Code blocks should use 4 spaces instead of tabs or any other indentation levels.

Warnings must go to the top of the section.

All abbreviatons must be capitalized.

HTML comments are not visiable in the rendered page.
Keep comment's content 1 space from the tag.
Use `WARNING: `, `NOTE: `, `TODO: `, `SORT: `, at the first line of comment and only when appropriate.

## Sorting config options

Config option tables are sorted in such manner:

{{% steps %}}

### Global toggle?

The `enabled` option must be always at first position.

### Display or display-like?

If table includes `output`, `position`, `scale`, `transform`, and `rotation`, they are put after `enabled`, if it exists, else at the top in the same order as they are specified here.

### Other

Left options are sorted by alphabet.

### Special order

If any additional sorting was performed, add a comment that starts with `SORT:` about it before the table.
Describe it in a free form, that is understandable for others and mention it in your PR.

{{% /steps %}}

## Option description

Description must start with capital letter and end without fullstop at the end.

Keep description concise, if it needs explanation, create named after the option paragraph and link it in the table.

If option only supports some predefined values, list them in the description.
If amount of predefined values is more than 4, then create named after the option paragraph and link it in the table.

If option has limits, that are enforced by config manager, they are specified in the `Limits` filed with respect to the type.
